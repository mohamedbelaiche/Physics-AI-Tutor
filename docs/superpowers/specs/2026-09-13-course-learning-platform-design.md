# تصميم: واجهة دورة تعليمية تتابعية (وحدات ← دروس ← عناصر) مع امتحانات وتعلّم تكيّفي

**التاريخ**: 2026-09-13
**الحالة**: معتمَد
**الفرع**: main

## 1. الخلفية والهدف

الموقع الحالي «المدرس الشخصي للفيزياء» يعرض وحدات (ملخصات PDF) مع مدرّس ذكي (OpenRouter).
المطلوب إضافة **واجهة ثانية** هي دورة تعليمية متسلسلة إجبارياً تُدرّس كل درس عبر «وحدات ← دروس ← عناصر/أجزاء»،
مع:
- عنصر واحد فقط يُعرض في كل خطوة، ولكل عنصر أمثلة.
- إمتحان في نهاية كل درس (QCM) يحدّد مستوى الطالب ونقاط قوته وضعفه ويُحفَظ في قاعدة بيانات الطالب.
- نفس بيانات القوة/الضعف تُستخدم في **بناء باقي عناصر الكورس** لتتوافق مع الطالب (تعلّم تكيّفي).
- إختبار شبيه بإمتحان الباكلوريا (QCM فقط) في نهاية كل وحدة.
- تتابع إجباري: لا يمكن دخول وحدة/درس إلا بعد إتمام ما قبله.
- إمتحان شامل نهائي (QCM) مثل الباكلوريا في نهاية الدورة لتحديد المستوى الحقيقي.

تم بناء نظام تعلّم تكيّفي سابق ثم حذفه (commit `c25417b`). هذا التصميم **يبني من الصفر** كما طلب المستخدم
ويأخذ دروس العيوب السابقة (بساطة، فصل أوضح بين المحتوى الثابت وحالة الطالب).

## 2. النطاق وخارجه

### في النطاق
- واجهة مستخدم جديدة «الدورة التعليمية» بجانب الواجهة الحالية «الملخصات».
- هيكل كورس: 5 وحدات (الوحدات الفيزياء الخمس للبكالوريا) ← دروس ← عناصر.
- بنك أسئلة QCM + آلية توليد امتحانات (درس/وحدة/نهائي).
- حفظ التقدّم والنتائج والمهارات لكل طالب في Supabase.
- تتابع إجباري مفرض من الخادم.
- تعلّم تكيّفي: شرح/أمثلة مخصصة للمهارات الضعيفة + أسئلة متدرجة الصعوبة.

### خارج النطاق (لهذا التطوير)
- تحرير المحتوى من داخل الواجهة (يتم عبر سكربت البناء ثم في الملفات).
- أدوار مدرّب/مشرف أو إدارة مستخدمين غير الطالب.
- إعادة تفعيل نظام التقييم التشخيصي (المحذوف) — مستوى الطالب يُبنى من إمتحانات الدروس.
- الوحدة «البرنامج السنوي» (extra) ليست جزءاً من الدورة.

## 3. البنية العامة

### الواجهة (SPA الحالية بدون إطار عمل)
شريط تنقّل علوي بتبويبين:
1. «الملخصات» — الواجهة الحالية (شبكة الوحدات + قارئ PDF) دون تغيير.
2. «الدورة التعليمية» — الواجهة الجديدة.

### المحتوى الثابت (ملفات JSON)
- `public/course/course.json` — شجرة الدورة: وحدات ← دروس ← عناصر.
- `public/course/questions.json` — بنك الأسئلة QCM.
تُحمَّل مباشرة من المتصفح بنفس نمط `public/units.json` الحالي. المحتوى لا يتغير لكل طالب؛
**حالة الطالب فقط** في قاعدة البيانات، والتكيّف يحدث عند الاستعمال.

### البيانات (Supabase — معدّلات جديدة، لا تمس جداول التشخيص)
| الجدول | الوصف |
|---|---|
| `course_progress` | حالة وحدة/درس/عنصر/إمتحان لكل طالب: locked/in_progress/completed/passed + أفضل درجة |
| `course_exam_attempts` | محاولات الامتحانات (lesson/unit/final): الحالة، المدة، الإجمالي، الصحيح، الدرجة، النجاح |
| `course_exam_answers` | إجابة كل سؤال في كل محاولة (سؤال، مهارة، صعوبة، خيار، صح/خطأ، زمن الاستجابة) |
| `course_skill_profiles` | إتقان الطالب لكل مهارة على مستوى الدورة (مستقل عن ملف التشخيص) |
| `student_learning_profile` | نبذة الطالب: المستوى العام، نقاط القوة/الضعف، موقعه الحالي، إعدادات التكيف |
| RPC `get_student_course_context()` | سياق مخصّص للمدرّس الذكي ولنقطة التكيّف |

قواعد RLS: كل جدول مقفول بأنماط تشابه جداول `.*_attempts` الموجودة (select/insert/update على صفوف الطالب نفسه).

### خادم API (نمط Vercel serverless كالموجود)
| المسار | الوظيفة |
|---|---|
| `GET /api/course/progress` | حالة الطالب + قائمة ما هو مفتوح/مقفول + أفضل الدرجات |
| `POST /api/course/progress` | إتمام عنصر/درس/وحدة/إمتحان بعد التحقق من التتابع |
| `GET /api/course/exam` | إنشاء امتحان (؟type=lesson\|unit\|final و ref) بتدرّج حسب الملف، مع إنشاء record للنشاط |
| `POST /api/course/exam/submit` | تصحيح، تحديث المهارات والملف، فحص النجاح، فتح التالي، حفظ الأجوبة |
| `POST /api/course/adapt` | شرح/أمثلة مخصصة من المدرّس الذكي لمهارة ضعيفة (مع بنك بديل عند الفشل) |

`server.js` يعرّف هذه المسارات الجديدة عبر `chatHandler`/`configHandler` النمط نفسه.

## 4. نموذج المحتوى

### `course.json`
```jsonc
{
  "version": 1,
  "title": "دورة الفيزياء — البكالوريا",
  "units": [{
    "id": "unit1",
    "title": "الوحدة الأولى",
    "description": "المتابعة الزمنية لتحول كيميائي في وسط مائي",
    "order": 1,
    "summary_pdf": "البيانات/الوحدة الأولى/الملخص/ملخص المتابعة الزمنية لتحول كيميائي.pdf",
    "exercises_pdf": "…/…/تجميعية_عمورة_للبكالوريات_السابقة_الوحدة_1.pdf",
    "lessons": [{
      "id": "u1l1",
      "title": "الأكسدة والإرجاع",
      "order": 1,
      "elements": [{
        "id": "u1l1e1",
        "title": "المؤكسد والمرجع وثنائيتا الأكسدة-الإرجاع",
        "skills": ["sk_justify"],
        "explanation": "… نص شرح من KNOWLEDGE_BASE …",
        "formulas": ["…"],
        "examples": [
          { "title": "مثال 1", "body": "…" },
          { "title": "مثال 2", "body": "…" }
        ]
      }]
    }]
  }]
}
```
- كل عنصر: `id`، عنوان، مهارة/مهارات، شرح، صيغ، أمثلة.
- أمثلة تُشتق من محتوى `KNOWLEDGE_BASE` (أمثلة محلولة/قوانين/جداول) داخل سكربت البناء.

### مصدر المحتوى
- `KNOWLEDGE_BASE/lessons/unit_0X_*.md` (خمسة ملفات): كل عنوان `## N.` = درس، والأجزاء `###`/فقراته = عناصر.
- `KNOWLEDGE_BASE/concepts/*.md` و `formulas/*.md` لتعزيز الشرح والأمثلة.
- الحقول الرئيسية `title_ar`/`concepts`/`skills` في front-matter تُستخدم لترتيب الدروس وربط العناصر بالمهارات.

### `questions.json`
```jsonc
{
  "version": 1,
  "questions": [{
    "id": "q-u1l1e1-01",
    "unit_id": "unit1", "lesson_id": "u1l1", "element_id": "u1l1e1",
    "skill": "sk_justify",
    "difficulty": 2,
    "question": "… النص …",
    "options": ["أ", "ب", "ج", "د"],
    "correct_index": 1,
    "explanation": "… سبب صحة الإجابة …"
  }]
}
```
- أول إصدار: 3–4 أسئلة مُؤلَّفة لكل عنصر من محتواه + توزيع أسئلة البنك التشخيصي الـ90 (`diagnostic_questions`) المناسبة على الوحدات/الدروس.
- البنك ينمو لاحقاً دون تغيير بنية.

## 5. بناء المحتوى

سكربت `scripts/build-course-content.js` (Node، يُشغَّل يدوياً):
1. يقرأ ملفات `KNOWLEDGE_BASE/lessons/*.md`.
2. يولّد `public/course/course.json` بالتفصيل أعلاه.
3. يولّد `public/course/questions.json` بدمج الأسئلة المُؤلَّفة (المدخلة داخل السكربت أو ملف إضافة منفصل) مع خرّيج أسئلة التشخيص.
4. يكتب تقرير فحص (`scripts/smoke-course.js` أيضاً) يتحقق: كل درس له عناصر، لا id مكرر، كل سؤال يشير لعنصر موجود، الخيارات 4 مع correct_index صالح.

## 6. التتابع الإجباري (قواعد الخادم)

- `element` التالي يُفتح فقط بعد إتمام الذي قبله (إتمام = مرور «العنصر التالي»، يُسجَّل في `course_progress`).
- «إمتحان الدرس» متاح فقط بعد إتمام **كل عناصر الدرس**.
- الدرس التالي يُفتح فقط بعد **نجاح إمتحان الدرس السابق**.
- «إختبار الوحدة» متاح فقط بعد نجاح كل دروس الوحدة.
- الوحدة التالية تُفتح فقط بعد نجاح إختبار الوحدة السابقة.
- «الإمتحان الشامل» متاح فقط بعد نجاح إختبارات الوحدات الخمس.
- الإعادة مسموحة؛ أفضل درجة تُحفظ؛ صفة «ناجح» تُثبت عند أول محاولة ناجحة.

العتبات:
- إمتحان درس: نجاح = **≥ 60%**.
- إختبار وحدة: نجاح = **≥ 50%**.
- الإمتحان الشامل: لا يُشترط نجاح (مقياس مستوى) لكن إتمامه يُثبت.

## 7. الامتحانات

| الإمتحان | المصدر | عدد الأسئلة | الغرض |
|---|---|---|---|
| درس | أسئلة عناصر الدرس | 5–8 | تحديد مستوى/قوة/ضعف مهارات الدرس |
| وحدة | أسئلة كل دروس الوحدة | 10–15 | تقييم على نمط الباكلوريا QCM |
| نهائي | كل بنك الدورة | 20–30 | تحديد المستوى الحقيقي الشامل |

حجم إمتحان الدرس محدود لكن بشرط تغطية العناصر: يُؤخذ **سؤال واحد على الأقل من كل عنصر** ثم تُستكمل العينة إلى 5–8 بأسئلة إضافية من نفس المهارات. لإختبار الوحدة: **سؤال واحد على الأقل من كل درس** ثم تُستكمل إلى 10–15. للإمتحان الشامل: عينة عشوائية موزونة تغطي كل الوحدات.
| وحدة | أسئلة كل دروس الوحدة | 10–15 | تقييم على نمط الباكلوريا QCM |
| نهائي | كل بنك الدورة | 20–30 | تحديد المستوى الحقيقي الشامل |

### توليد الأسئلة المتدرج (تكيّف الصعوبة)
- من ملف الطالب `course_skill_profiles` نعرف إتقان كل مهارة (0–100).
- عند بناء الامتحان: المهارات الضعيفة تأخذ أسئلة مستوى (1–3) أولاً ثم تصاعد؛ المهارات المتقنة (≥70) تأخذ (3–5).
- التسلسل: أسهل→أصعب داخل نفس المهارة، وخلط عشوائي بين المهارات.
- الإجابات محددة، ولا تُرسل مع نص الامتحان.

## 8. طريقة التصحيح وتحديث ملف الطالب

عند `POST /api/course/exam/submit`:
1. تصحيح كل إجابة مقابل `correct_index` من `questions.json` (يقرأ الخادم نفس الملف).
2. حساب درجة لكل مهارة (نسبة الإجابات الصحيحة ضمن أسئلة المهارة في هذه المحاولة) ودمجها في `course_skill_profiles` بالمعادلة: `mastery_جديد = 0.6 × درجة_المحاولة + 0.4 × mastery_سابق` مع احتساب العينات (كلما زادت العينات ثَبُت المتوسط).
3. تحديث `student_learning_profile`: المستوى العام (من متوسط الإتقان)، `strengths` (مهارات ≥70)، `weaknesses` (مهارات <50)، `current_position`.
4. تخزين `course_exam_attempts` + `course_exam_answers` مع صنف الخطأ إن أمكن (conceptual/calculation/…).
5. فحص النجاح مقابل العتبة وتحديث `course_progress` (درجة/حالة/فتح).
6. الرد: الدرجة، تفصيل المهارات، القوة/الضعف، نجاح/رسوب، العنصر/الدرس/الوحدة التالي.

## 9. التعلّم التكييفي

### أ) محتوى مخصص داخل الدرس
- في `GET /api/course/progress` وأثناء عرض عنصر، يفحص الخادم مهارات العنصر مقابل `weaknesses`.
- إذا كان الطالب ضعيفاً في مهارة العنصر تُعرض بطاقة «اشرح لي بطريقة أبسط» (وكأنها محتوى إضافي):
  - `POST /api/course/adapt` { lesson_id, element_id, skill, weakness_info }.
  - يستدعي OpenRouter (نفس نمط `api/chat.js`) بسياق مركّز من `course.json` + ملف الطالب فيولّد شرحاً مبسّطاً + مثالاً تطبيقياً إضافياً مخصصاً لنوع الخطأ.
  - عند فشل الذكاء الاصطناعي: يُعاد مثال إضافي محفوظ من `questions.json`/`course.json` دون تعطيل.
- يُخزَّن التوليد مبدئياً في `student_learning_profile.adaptation_overrides` لتقليل الاستدعاءات المتكررة.

### ب) أسئلة متدرجة
كما في القسم 7 — تُرجَّح الصعوبة حسب الإتقان في كل امتحان.

## 10. واجهة المستخدم

تنظيم الملفات:
- إضافة أقسام `view` جديدة داخل `index.html` (بنمط `home-view`/`reader-view` الحالي) + `public/course.js` + أنماط جديدة في `style.css`.

الشاشات:
1. **لوحة الدورة**: بطاقات الوحدات (مقفول/مفتوح/ناجح%) + شريط تقدّم عام.
2. **درس**: عنصر واحد فقط (شرح + أمثلة + صيغ) + زر «العنصر التالي» + مؤشر التقدم (مثال: 2/6). أزرار مرجعية لملفات PDF إذا وُجدت.
3. **إمتحان درس/وحدة/نهائي**: سؤال واحد في الشاشة، اختيار خيار ثم «تالي»، ومراجعة قبل الإرسال، ثم شاشة النتيجة.
4. **شاشة النتيجة**: الدرجة، مستوى المهارات كنقاط قوة/ضعف، نجاح/رسوب، ثم زر (المتابعة / إعادة الإمتحان / المراجعة بالشرح المبسّط).
5. **التكيّف**: بطاقة شرح مبسّط قابلة للطي داخل الدرس عند المهارات الضعيفة.

اللغة/الاتجاه: عربي RTL، بنفس نمط `style.css` الحالي.

## 11. تدفق الطالب النموذجي
1. يفتح «الدورة التعليمية» → الوحدة 1 مفتوحة، البقية مقفلة.
2. يفتح وحدة 1 → أول درس مفتوح.
3. يعرض العنصر 1 (شرح+أمثلة) → «التالي» → … → بعد آخر عنصر تُفعَّل «إمتحان الدرس».
4. نتيجة جيدة → درس 2 يُفتح. نتيجة ضعيفة → رسوب، يُعرض الشرح المبسّط/إعادة.
5. بعد نجاح كل دروس الوحدة → «إختبار الوحدة» ثم فتح الوحدة 2.
6. بعد كل الوحدات → «الإمتحان الشامل» ونتيجته تحدد المستوى النهائي.

## 12. معالجة الأخطاء والموثوقية
- فشل OpenRouter: Fallback إلى بنك الأمثلة المحفوظة؛ لا يتعطل الدرس، ورسالة «التخصيص غير متاح حالياً».
- الجلسة منتهية: كل نقاط API تعيد 401 فتفتح الواجهة نافذة الدخول (مثل chat).
- تعارض المحتوى: إذا كُسِر `course.json` (id خاطئ) يفشل `GET /api/course/progress` برسالة واضحة بدل Silently، والـ smoke يمسك هذا قبل النشر.
- التقدّم محلي للطالب: لا كسر بين مستخدمين.
